# Deployment Guide

This guide covers deploying the Liking Rating Database to Render for free hosting.

## 🌟 Overview

The application consists of:
- **Backend**: Python FastAPI with PostgreSQL database
- **Frontend**: React static site
- **Database**: PostgreSQL (800MB+ of research data)

## 🚀 Quick Deploy to Render

### Prerequisites
- GitHub account
- Render account (free)
- Git repository pushed to GitHub

### Step 1: Prepare Your Repository

1. Ensure your code is committed and pushed to GitHub:
```bash
git add .
git commit -m "Prepare for Render deployment"
git push origin main
```

### Step 2: Deploy to Render

1. **Go to [Render Dashboard](https://dashboard.render.com/)**

2. **Click "New +" → "Blueprint"**

3. **Connect your GitHub repository**

4. **Render will automatically detect the `render.yaml` file and create all services:**
   - PostgreSQL database
   - Backend API service
   - Frontend static site

### Step 3: Database Migration

After deployment, migrate your data:

1. **Get your PostgreSQL connection string from Render dashboard**

2. **Run the migration locally** (with production database URL):
```bash
export DATABASE_URL="postgresql://user:password@host:port/database"
python scripts/migrate_to_postgresql.py
```

### Step 4: Access Your App

Your app will be available at:
- **Frontend**: `https://liking-rating-frontend.onrender.com`
- **Backend API**: `https://liking-rating-api.onrender.com`
- **API Docs**: `https://liking-rating-api.onrender.com/api/v1/docs`

## 🔧 Manual Setup (Alternative)

If you prefer manual setup:

### 1. Create Services Manually

#### Database Service
```bash
# Create PostgreSQL database
render services create database \
  --name liking-rating-postgres \
  --database-name liking_rating_db \
  --user liking_user
```

#### Backend Service
```bash
# Create web service for API
render services create web \
  --name liking-rating-api \
  --env docker \
  --dockerfile-path ./Dockerfile \
  --health-check-path /health
```

#### Frontend Service
```bash
# Create static site for frontend
render services create static \
  --name liking-rating-frontend \
  --build-command "cd frontend && npm ci && npm run build" \
  --publish-path "./frontend/build"
```

### 2. Set Environment Variables

In your Render service settings, add:

#### Backend Environment Variables
```
DATABASE_URL=<auto-generated-postgres-url>
SECRET_KEY=<auto-generated-secret>
API_HOST=0.0.0.0
PORT=8000
LOG_LEVEL=INFO
BACKEND_CORS_ORIGINS=https://liking-rating-frontend.onrender.com
TRUSTED_HOSTS=localhost,127.0.0.1,*.onrender.com
```

#### Frontend Environment Variables
```
REACT_APP_API_URL=https://liking-rating-api.onrender.com/api/v1
NODE_ENV=production
GENERATE_SOURCEMAP=false
```

## 🔍 Troubleshooting

### Common Issues

#### 1. CORS Errors
Update `BACKEND_CORS_ORIGINS` to include your frontend URL:
```
BACKEND_CORS_ORIGINS=https://your-frontend.onrender.com,http://localhost:3000
```

#### 2. Database Connection Failed
- Verify `DATABASE_URL` is set correctly
- Check PostgreSQL service is running
- Ensure database credentials are correct

#### 3. Frontend API Calls Failing
- Verify `REACT_APP_API_URL` points to your backend
- Check backend service is running and healthy
- Verify CORS configuration

#### 4. Build Failures
- Check Node.js version (requires 16+)
- Verify all dependencies are in package.json
- Check build logs for specific errors

### Health Checks

#### Backend Health

## 📈 Performance Considerations

### Render Free Tier Limitations
- **Spin-down**: Services sleep after 15 minutes of inactivity
- **Cold starts**: First request after sleep takes ~30 seconds
- **Storage**: 1GB database storage limit
- **Bandwidth**: 100GB/month transfer limit

### Optimizations
- **Database Indexing**: Pre-configured for common queries
- **Response Compression**: Enabled via FastAPI
- **Static Asset Caching**: Automatic via Render CDN
- **Connection Pooling**: Configured for PostgreSQL

## 🔒 Security

### Production Security Features
- **HTTPS**: Automatic SSL certificates
- **CORS**: Configured for production domains
- **Trusted Hosts**: Limited to known domains
- **Environment Variables**: Sensitive data in env vars
- **Database Security**: PostgreSQL with user authentication

### Security Best Practices
- ✅ No secrets in source code
- ✅ Environment-based configuration
- ✅ HTTPS-only in production
- ✅ Database connection encryption
- ✅ Proper CORS configuration
